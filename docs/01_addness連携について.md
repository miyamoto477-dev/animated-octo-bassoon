# addness社との連携について（検討中）

## これは何か

「addness」は、AIを教えるスクールを運営している会社です。
このドキュメントは、addness社が提供するサービス（会員サイト・LMSなど）とのログイン連携（API/OAuth連携）を将来的に実装するための、現時点での想定仕様メモです。

## 現在のステータス

**未実装**。addness社側のAPI仕様書・認証方式（OAuth2.0かAPIキー方式か等）・エンドポイントURLがまだ確定していないため、実装には着手していません。

存在しないAPI仕様に対して憶測でコードを書くと、動作しない・誤ったリクエストを送ってしまう恐れがあるため、以下の情報が揃ってから実装に着手します。

## 実装に必要な情報（addness社から取得が必要）

- [ ] API仕様書（エンドポイント一覧・リクエスト/レスポンス形式）
- [ ] 認証方式（OAuth2.0 / APIキー / その他）
- [ ] OAuth2.0の場合：認可エンドポイントURL・トークンエンドポイントURL・スコープ一覧
- [ ] client ID／client secretの発行方法
- [ ] 連携で取得したいデータ・実行したい操作（例：受講生情報の取得、ログイン状態の確認など）

## 想定している設定項目（実装時のプレースホルダ）

実装時は、認証情報を平文でリポジトリに保存せず、環境変数または`.env`（`.gitignore`対象）で管理する想定です。

```text
ADDNESS_CLIENT_ID=
ADDNESS_CLIENT_SECRET=
ADDNESS_OAUTH_AUTHORIZE_URL=
ADDNESS_OAUTH_TOKEN_URL=
ADDNESS_API_BASE_URL=
```

## 次のステップ

1. addness社の担当窓口からAPI仕様書を入手する
2. 上記チェックリストの情報を本ドキュメントに追記する
3. 情報が揃い次第、実装方針（このリポジトリ内に組み込むか、別リポジトリ・別サービスとして構築するか）をあらためて検討する
