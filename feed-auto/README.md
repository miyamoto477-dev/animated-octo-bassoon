# feed-auto｜Instagramフィード自動投稿

`pending/` に画像とキャプションのペアを入れておくと、毎日決まった時刻（例：朝9時）に1件ずつ自動でInstagramフィードに投稿し、投稿済みは `posted/` に自動で移動するしくみです。同じ投稿が二重に送られることはありません（投稿し終えたペアは必ず `pending/` から退避するため）。

**初回セットアップは [`セットアップ手順.md`](./セットアップ手順.md) を参照してください。** Instagramビジネス/クリエイターアカウントへの切り替え、Metaアクセストークンの発行、imgbb APIキーの取得、Windowsタスクスケジューラへの登録までを順番に説明しています。

## フォルダ構成

```
feed-auto/
  pending/   ← ここに「画像 + 同名のキャプション.txt」を入れる（投稿待ち）
  posted/    ← 投稿に成功したペアが自動で移動してくる（投稿済み）
  failed/    ← 投稿に失敗したペアが移動してくる（原因は同名の .error.txt を確認）
  logs/      ← post_log.csv に全実行の履歴が残る
  scripts/   ← 実行スクリプト本体（post_to_instagram.py）
  .env       ← 認証情報（.env.example をコピーして作成。Gitには入らない）
```

## 投稿の入れ方

1. 画像ファイル（`.jpg` / `.jpeg` / `.png` / `.webp`）と、同じファイル名でキャプションを書いた `.txt` ファイルを1組にして `pending/` に入れる。
   - 例：`001_美容室オープン告知.jpg` と `001_美容室オープン告知.txt`
2. ファイル名は**投稿したい順に並ぶよう**、先頭に連番や日付を付ける（`001_...` `002_...` や `2026-08-20_...` など）。スクリプトはファイル名順で一番先頭のペアから1件だけ投稿します。
3. キャプションが見つからない画像はスキップされ、`pending/` に残ったまま次回以降に持ち越されます（投稿は消費されません）。

## 動作の仕組み

- 1回の実行につき、投稿は**必ず1件だけ**。
- 成功したペアは `posted/` へ移動 → 二重投稿防止。
- 失敗したペアは `failed/` へ移動し、原因を `〇〇.error.txt` に記録（キューが止まらないよう、失敗しても次回は次のペアに進みます）。
- `.env` の設定漏れなど「投稿前の設定エラー」の場合はペアを消費せず、次回同じペアで再試行します。
- 実行の重複防止のため `.lock` ファイルを使用（前回の実行が15分以内に始まっていれば今回はスキップ）。
- 実行結果はすべて `logs/post_log.csv` に追記されます。

## 手動でテストする

Instagramの認証情報を用意する前に、フォルダの動き（ファイルの選び方・移動）だけを確認したい場合：

```bash
python feed-auto/scripts/post_to_instagram.py --dry-run
```

実際のAPI呼び出しは行わず、`pending/` の先頭ペアを `posted/` に移動するだけの動作確認ができます。

本番と同じ動きを確認する場合（`.env` 設定後）：

```bash
python feed-auto/scripts/post_to_instagram.py
```

## 投稿時刻の変更

`セットアップ手順.md` のタスクスケジューラ登録手順で指定した時刻を変更すれば、投稿時刻を変えられます（スクリプト自体には時刻の指定はなく、呼び出す側＝タスクスケジューラ/cronが時刻を管理します）。

## 注意事項

- `.env` に入るアクセストークンは他人と共有しないこと。誤って共有した場合はMeta for Developersですぐに無効化・再発行してください。
- Meta発行の長期アクセストークンは約60日で失効します。失効が近いと実行時に警告が表示されるので、その際は `セットアップ手順.md` の手順で再発行してください。
- `pending/` `posted/` `failed/` の中身（画像・キャプション・ログ）はGit管理対象外（`.gitignore`）です。ローカルにのみ保存されます。
