# AI社員10人組織｜チーム編成ガイド

## これは何か

ルートの `CLAUDE.md` は「企画から営業提案まで何でも1人でこなすAI社員」1人分の定義。
この `team/` フォルダは、それを**10人の役職に分業した組織**として使いたい場合の拡張版。

フォルダ1つ＝AI社員1人。それぞれに専用の `CLAUDE.md` が入っており、そのフォルダでClaude Codeを開くと、その役職として振る舞う。

## 組織図（工程の流れ）

```text
                 01 統括ディレクター（全体設計・工程管理・品質チェック）
                              │
   ┌───────────┬──────────┼──────────┬─────────────┐
   ▼               ▼               ▼               ▼             ▼
02 企画担当 → 03 台本担当 → 04 サムネ ┐  05 撮影編集    06 投稿運用管理
                              デザイン担当 │  アドバイザー   担当（投稿・スケジュール）
                                       └──────┴──────┬────────┘
                                                      ▼
                                          07 データ分析担当
                                                      │
                                                      ▼
                                          08 クライアント報告担当
                                                      │
                                                      ▼
                                          10 カスタマーサクセス担当（継続・関係構築）

09 営業診断担当（新規見込み客への診断・提案書、既存とは別ライン）
```

## 使い方

### パターンA｜これまで通り、1人のAI社員に何でも相談する

ルートフォルダで `claude` を起動すればよい（ルートの `CLAUDE.md` がそのまま使われる）。今まで通りの使い方。

### パターンB｜役職ごとに分けて相談したい

その役職のフォルダに移動してから `claude` を起動する。

```bash
cd team/02_企画担当
claude
```

```text
あなたの役割を教えて
```

と聞き、企画担当として名乗れば成功。以降はその役職の視点だけで会話が進む。

### パターンC｜チームとして横断的に相談したい

`01_統括ディレクター` のフォルダで起動する。ディレクターが工程を整理し、該当する担当フォルダを案内してくれる。

## 全体ルール

10人共通のルールは `RULES.md` にまとめている。各役職の `CLAUDE.md` は、このルールに従うことを前提に書かれている。

## メモリ

アカウント情報は `../memory/account-profile.md` を全役職で共有する。役職ごとに情報を分断しない。
